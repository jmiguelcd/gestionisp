01 ¿Qué es Fosmikro?

Fosmikro es un sistema de gestión para ISPs (proveedores de internet) de tamaño pequeño a mediano, desarrollado en Ecuador. Reemplaza soluciones costosas como SmartOLT o ISP Cube con una plataforma 100% propia, extensible y desplegada en la nube.

Problemas que resuelve

  • Gestión de clientes, contratos y planes de internet desde un solo lugar
  • Control de ONTs/ONUs en OLTs Huawei, ZTE y V-SOL vía SSH
  • Configuración remota de WiFi y PPPoE en equipos del cliente (TR-069/GenieACS)
  • Facturación electrónica válida para el SRI Ecuador (XAdES BES)
  • Corte y reconexión automática de servicio (RADIUS + MikroTik)
  • Monitoreo de señal óptica y alertas NOC en tiempo real
  • Mapa de planta externa: tendido de fibra, splitters, nodos
  • Multi-empresa (multi-tenant) con aislamiento de datos por RLS

Arquitectura general

El sistema corre en una VM Oracle Cloud Free Tier (ARM64) con un túnel WireGuard hacia la red del ISP, permitiendo que el backend alcance las OLTs y MikroTiks de forma segura desde internet.

# Vista de alto nivel
Browser ──HTTPS──▶ nginx (80) ──▶ Vue 3 SPA

                                     ├──▶ GenieACS NBI (TR-069)

                                     └──WireGuard──▶ OLT / MikroTik (LAN ISP)

06 Prompt completo para Claude Code

Este es el prompt de arranque que le das a Claude Code la primera vez para que entienda el proyecto completo. Cópialo en tu primera sesión después de crear el scaffold.

CONTEXTO DEL PROYECTO

Estamos construyendo Fosmikro, un sistema de gestión completo para ISPs (proveedores de internet por fibra óptica) en Ecuador. El sistema reemplaza soluciones comerciales como SmartOLT o ISP Cube con una plataforma 100% propia, multi-tenant y desplegable en la nube.

STACK TECNOLÓGICO

Frontend: Vue 3 + TypeScript + Vite 6, Tailwind CSS v4 con @tailwindcss/vite, Pinia para estado global, Vue Router 4 para navegación con lazy loading. Backend: Hono framework sobre Node.js 22 (ESM + TypeScript via tsx), exponiendo una API REST y actuando como proxy SSH hacia OLTs. Base de datos: Supabase (PostgreSQL + GoTrue Auth + Row Level Security multi-tenant). Infraestructura: Docker Compose con nginx (frontend), Node.js backend, GenieACS (cwmp/nbi/ui), MongoDB (datos TR-069), FreeRADIUS. Deploy en Oracle Cloud Free Tier ARM64 con WireGuard para túnel a la LAN del ISP.

DESIGN SYSTEM

Tema oscuro "cyber tech". Variables CSS definidas en :root en src/assets/main.css: --fm-bg-0 (#080c14) a --fm-bg-3 (#162038) para fondos, --fm-border (#1e3050) y --fm-border-bright (#2a4570) para bordes, --fm-text-1 (#e2e8f0) a --fm-text-3 (#3d5270) para texto, --fm-cyan (#00d4ff) como acento principal, --fm-violet (#7c3aed) como acento secundario. NUNCA usar colores Tailwind hardcodeados para fondos/texto principales. Los botones de acción tienen colores propios (blue, green, orange, red). Fuente: Inter + Cascadia Code para monoespaciado.

ARQUITECTURA DE MÓDULOS

1. Auth/Login: Supabase Auth con email+password. Guard de rutas en Vue Router. Soporte multi-tenant: cada usuario pertenece a una tenant_id. Row Level Security activo en todas las tablas.

2. Gestión de clientes: Tabla clients con estados (prospect → pending → active → suspended → cut → retired). Contratos de servicio, planes, direcciones de instalación. Historial de estados. Documentos. Vista de ficha completa con kardex de cobros.

3. OLTs y ONTs: Tabla olt_devices (brand: huawei/zte/vsol, IP, credenciales SSH). Driver por marca: Huawei MA5800, ZTE C320, V-SOL. Listado de ONTs en tiempo real por puerto PON. Provisión (agregar ONT a un puerto), desprovisión, cambio de modo. Panel de señal óptica por ONT.

4. Facturación: Planes con precio, velocidad. Generación masiva de facturas por mes. Comprobantes electrónicos SRI Ecuador (factura + nota de crédito + nota de débito) firmados digitalmente con XAdES BES usando el certificado .p12 del cliente. PDF en formato RIDE. Caja y cobros por abonado.

5. TR-069/GenieACS: Proxy /api/genieacs → GenieACS NBI. Panel de configuración de WiFi (SSID, clave, canal, frecuencia), WAN/PPPoE (usuario, contraseña), diagnóstico ping/traceroute desde la ONT, actualización de firmware, reset de fábrica. Modo "legacy" via enlace directo a GenieACS UI.

6. MikroTik: API RouterOS para gestión de usuarios PPPoE, pools de IP, firewall, blocking, VLANs, balanceo de carga, monitoreo de interfaces. Integración con corte de servicio por falta de pago.

7. RADIUS/BRAS: FreeRADIUS como servidor de autenticación PPPoE. API para crear/editar/eliminar abonados en radcheck. CoA (Change of Authorization) para corte en tiempo real. Integración con el módulo de cortes automáticos por deuda.

8. NOC y monitoreo: Dashboard de señal óptica (Rx power por ONT). Alertas configurables (umbral de señal, estado offline). Gráficas de disponibilidad. Mapa de calor de fallos por zona.

9. Mapa de fibra OSP: Leaflet.js con capas para nodos (OLTs, splitters, cajas de empalme), tendido de cables (polilíneas), reserva de fibras. Vista de árbol PON. Valoración estimada de la planta (USD por metro de cable).

10. CRM: Tickets de soporte, campañas de WhatsApp (API de Meta), agenda de instalaciones, reportes de desconexiones.

MULTI-TENANT

Cada ISP es una "tenant". La tabla tenants almacena nombre, RUC, logo, configuración SRI. Todas las tablas tienen tenant_id con políticas RLS: `(tenant_id = auth.jwt()->>'tenant_id')`. Los usuarios se asignan a un tenant al registrarse. El sistema soporta múltiples ISPs independientes en la misma instancia.

PATRONES DE CÓDIGO

Componentes Vue siempre con <script setup lang="ts">. API calls a través de servicios en src/services/ (olt.ts, genieacs.ts, mikrotik.ts, etc.). Stores Pinia en src/stores/. Tipos TypeScript en src/types/database.ts generados o mantenidos manualmente desde el schema de Supabase. Migraciones SQL numeradas en supabase/migrations/001_....sql. Backend Hono: rutas en server/src/routes/, drivers OLT en server/src/drivers/. Las respuestas de error siempre incluyen { error: string }. Los endpoints SSH usan ssh2 con keyboard-interactive + password auth, cooldown de 300ms entre comandos.

INSTRUCCIONES PERMANENTES

— Responde siempre en español.
— Sin comentarios obvios en el código; solo cuando el WHY no sea evidente.
— No crear archivos README ni documentación a menos que se pida explícitamente.
— Prefiere editar archivos existentes a crear nuevos.
— Para popups/modales complejos: usar window.open() hacia una ruta Vue dedicada (Teleport con dialog puede fallar en contextos anidados).
— Los CSS de la UI usan variables --fm-* del design system, NO clases Tailwind de color hardcodeadas.
— Al desplegar: usar --no-deps --pull never en docker compose up para evitar errores de imagen genieacs.

Prompt

Implementa el módulo TR-069 de Fosmikro:

- Sección PPP Interface: usuario/clave PPPoE, estado WAN, IP externa

Flujo de detección:
- Buscar el dispositivo en GenieACS por número de serie o IP de gestión

F11 Fase 11 — Deploy a producción

Objetivo

Desplegar el sistema completo en Oracle Cloud Free Tier con Docker Compose, HTTPS automático y túnel WireGuard hacia la LAN del ISP.

Prompt

Configura el deploy de producción de Fosmikro:

  nginx sirve el dist/ y hace proxy /api → backend
- backend: Node.js con tsx, variables de entorno desde .env del VPS
- genieacs-cwmp, genieacs-nbi, genieacs-ui, genieacs-fs: imágenes genieacs/genieacs:1.2
- mongodb: mongo:6 (solo para GenieACS)
- freeradius: (imagen custom con raddb configurado)

deploy/Dockerfile.frontend: multi-stage (node:22-slim build + nginx:alpine serve)
deploy/Dockerfile.backend: node:22-slim con tsx

deploy/nginx.conf:
- Proxy /api → backend:3002
- SPA fallback a index.html
- Cache 30d para /assets/ (hashed)
- NO-cache para index.html (no-store, must-revalidate)

deploy/setup-vps.sh:
- Instalar Docker + Compose en Ubuntu 22.04 ARM64
- Instalar WireGuard
- Clonar repo y levantar el stack

Script de actualización (un solo comando):
ssh -i key ubuntu@IP "cd ~/fosmikro && git pull && \
  sudo docker compose -f docker-compose.cloud.yml build --no-cache frontend backend && \
  sudo docker compose -f docker-compose.cloud.yml up -d --no-deps --pull never frontend backend"

Configuración WireGuard

# /etc/wireguard/wg0.conf en el VPS (concentrador)
[Interface]
Address = 10.200.0.1/16
ListenPort = 51820
PrivateKey = <VPS_PRIVATE_KEY>

[Peer]  # MikroTik del ISP (sitio 1)
PublicKey = <MIKROTIK_PUBLIC_KEY>
AllowedIPs = 10.200.1.0/24
PersistentKeepalive = 25

# En el MikroTik RouterOS:
# /interface wireguard peers add interface=wg-fosmikro public-key="<VPS_PUB>" endpoint-address=<VPS_IP>:51820
# /ip route add dst-address=0.0.0.0/0 gateway=wg-fosmikro  (solo tráfico fosmikro)
# /ip firewall nat add chain=dstnat dst-address=10.200.1.2 action=dst-nat to-addresses=192.168.1.100  (OLT)
